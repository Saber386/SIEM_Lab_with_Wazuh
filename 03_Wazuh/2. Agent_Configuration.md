# Windows Agent Configuration

## Objective

After successfully deploying the Wazuh Server on an Ubuntu virtual machine, my next objective was to onboard my Windows 11 host as the first monitored endpoint. This would allow the Wazuh Manager to receive telemetry from the Windows system and verify that the SIEM environment was functioning correctly.

---

# Lab Environment

| Component | Details |
|-----------|---------|
| Host Machine | Windows 11 |
| Wazuh Server | Ubuntu 24.04 LTS (VirtualBox) |
| Wazuh Version | 4.14.6 |
| Network Mode | Bridged Adapter |
| Manager IP | 10.157.129.127 |

---

# Preparing the Network

Initially, my Ubuntu virtual machine was configured with **NAT** networking. The VM received the IP address:

```
10.0.2.15
```

Although internet connectivity worked, the Windows host could not communicate directly with the Wazuh Manager.

To solve this, I powered off the virtual machine and changed the VirtualBox network configuration from **NAT** to **Bridged Adapter**.

After restarting the VM, I verified the new IP address using:

```bash
hostname -I
```

The server received the following IP:

```
10.157.129.127
```

This address was later used while deploying the Windows agent.

> **Screenshot:** VirtualBox Bridged Network Configuration

---

# Deploying the Windows Agent

From the Wazuh Dashboard, I navigated to:

```
Dashboard
→ Agents
→ Deploy New Agent
```

I selected:

- Operating System: Windows
- Architecture: x64
- Manager Address: 10.157.129.127
- Group: Default

The deployment wizard generated a PowerShell installation command.

> **Screenshot:** Deploy New Agent Wizard

---

# Installing the Agent

I launched **PowerShell as Administrator** on my Windows host and executed the generated installation command.

The installer downloaded and configured the Wazuh Agent automatically.

During installation, I noticed that Windows Installer displayed the following dialog:

```
Change
Repair
Remove
```

This indicated that the Wazuh Agent had already been installed successfully, so there was no need to reinstall it.

> **Screenshot:** Windows Installer Prompt

---

# Starting the Agent Service

To verify the installation, I checked whether the Windows service existed.

```powershell
Get-Service WazuhSvc
```

The service was successfully detected.

I then started it using:

```cmd
NET START WazuhSvc
```

The service started without errors.

> **Screenshot:** Starting Wazuh Service

---

# Verifying Agent Registration

After refreshing the Wazuh Dashboard, the Windows endpoint appeared under **Agents**.

The dashboard reported:

- Status: Active
- Version: 4.14.6
- Operating System: Windows 11
- Group: Default

This confirmed that the Windows endpoint was successfully communicating with the Wazuh Manager.

> **Screenshot:** Active Windows Endpoint

---

# Challenges Faced

## 1. Incorrect Network Configuration

Initially, the virtual machine was configured using NAT networking.

Because of this, Windows could not communicate with the Wazuh Manager.

### Resolution

Changed the VirtualBox network adapter to **Bridged Adapter** and obtained a reachable IP address.

---

## 2. Incorrect Service Name

While attempting to start the agent, I initially used:

```powershell
Start-Service Wazuh-Svc
```

PowerShell returned an error because the service name was incorrect.

### Resolution

The correct service name is:

```cmd
NET START WazuhSvc
```

After using the correct service name, the agent started successfully.

---

## Lessons Learned

- Bridged networking is essential when endpoints need to communicate directly with the Wazuh Manager.
- Always verify the server IP address before deploying an agent.
- Confirm that the Wazuh service is running before troubleshooting connectivity issues.
- A successful installation does not always mean the service is active; service verification is equally important.
- The Wazuh Dashboard provides a quick way to confirm whether an endpoint has successfully registered.
