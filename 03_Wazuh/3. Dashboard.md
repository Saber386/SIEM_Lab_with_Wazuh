# Wazuh Dashboard

## Objective

After completing the Wazuh installation and successfully connecting my Windows 11 endpoint, I explored the Wazuh Dashboard to verify that the SIEM platform was functioning correctly. My primary objective was to ensure that all core services were operational and that the Windows agent was actively communicating with the Wazuh Manager.

---

# Accessing the Dashboard

Once the installation was complete, I accessed the dashboard from the Ubuntu virtual machine using:

```
https://localhost
```

Since Wazuh uses a self-signed SSL certificate by default, the browser displayed a security warning before opening the dashboard. After accepting the warning, I logged in using the administrator credentials generated during the installation process.

# Dashboard Overview

After logging in, I was presented with the Wazuh Dashboard, which serves as the central monitoring interface for the entire SIEM environment.

The dashboard provides quick access to multiple modules including:

- Dashboard
- Endpoints
- Security Events
- Threat Intelligence
- Vulnerability Detection
- Inventory
- Rules
- Discover
- Server Management

Each module focuses on a different aspect of monitoring and security analysis.

# Verifying Endpoint Connectivity

The first thing I verified was whether the Windows endpoint had successfully connected to the Wazuh Manager.

I navigated to:

```
Endpoints → Agents
```

The Windows 11 endpoint appeared with the following information:

| Property | Status |
|----------|--------|
| Agent Status | Active |
| Operating System | Windows 11 |
| Version | 4.14.6 |
| Group | Default |

This confirmed that communication between the Windows Agent and the Wazuh Manager had been established successfully.

During my initial exploration, I became familiar with several important sections of the dashboard.

## Dashboard

Provides an overall health summary of the SIEM environment and connected endpoints.

## Endpoints

Displays every connected endpoint along with its status, operating system, version, and assigned group.

This section is useful for confirming that agents are communicating successfully with the manager.

## Security Events

Displays security-related events collected from connected agents.

At this stage, only a limited number of events were available because no attack simulations or monitoring activities had been performed yet.

## Inventory

The Inventory module collects information about monitored systems, including installed software, operating system details, hardware information, and other asset-related data.

As the agent continues communicating with the manager, this information is updated automatically.

# Lessons Learned

Exploring the dashboard helped me understand how Wazuh centralizes security monitoring into a single interface.

Some key observations from this phase include:

- Successfully installing the platform is only the first step.
- Agent connectivity is essential before any monitoring can begin.
- Most dashboard modules remain empty until endpoints start generating telemetry.
- The dashboard provides an effective way to verify the overall health of the SIEM environment.

---

# Conclusion

At the end of this phase, I successfully verified that the Wazuh Dashboard was functioning as expected.

The dashboard confirmed that:

- The Wazuh platform was fully operational.
- The Windows 11 endpoint was connected successfully.
- Communication between the endpoint and the manager was active.
- The SIEM environment was ready for log collection, monitoring, and threat detection.
